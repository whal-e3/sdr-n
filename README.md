# OrbitScope

<img src="docs/branding/orbitscope-logo.png" alt="OrbitScope logo" width="160" />

Experimental, receive-only Android app for tracking cataloged satellites and inspecting curated public/amateur downlinks with a USB software-defined radio. Sky browses orbital records with or without radio metadata, calculates passes across a local day, and offers an offline interactive 3D globe. Location can follow the phone's GPS/network fix, use an offline world map, or accept manual coordinates. Target shows look angle, passes, and downlink eligibility. Signal displays the receiver chain, frequency spectrum, spectrogram, time-domain IQ, and raw IQ constellation view. It includes experimental NFM voice audio and Bell 202 AFSK1200/AX.25 packet decoding, tested with synthetic signals only. **Meteor LRPT imagery decoding is not implemented yet.**

## Name and logo

OrbitScope combines orbital observation and signal inspection. The app name appears in the Android launcher, system permission dialogs, screen header, and receiver notifications. The orbital logo is included in the launcher icon and [branding assets](docs/branding/). The release candidate uses `io.github.whal_e3.orbitscope`. It installs separately from the earlier `org.satelliteeavesdropper.app` development build; that build's private catalog, imports and settings are not migrated automatically. Finalize the ID before the first Play upload.

## Build and run

For publication preparation, signing, release checks and store requirements, see [Publishing OrbitScope](docs/release/PUBLISHING.md). The release is still experimental; building an AAB does not configure a current catalog or publish the app. **About** provides offline privacy information and bundled licenses. Store assets and submission notes are in `docs/release/`.

1. Install Android Studio with Android SDK Platform 36, Build Tools 36.x, NDK 27.0.12077973, CMake, and a JDK 17. Use a physical Android 10+ phone with USB host/OTG support for SDR testing; an arm64 device is preferred. The x86_64 build target is for emulator UI/test-tone checks only.
2. Open this repository as a project in Android Studio and let Gradle sync. Select the `app` run configuration and launch it. Alternatively, run `./gradlew.bat :app:assembleDebug` from PowerShell.
3. Grant location permission when asked so the observer follows the phone automatically. If Android stops offering the grant prompt after denial, Location offers **Open app settings**. The Location tab also has a map and manual coordinates. Each fresh GPS fix updates the active position, while Sky recalculates its broad day schedule after about 100 m of movement. Sky lists every orbital record in the loaded catalog; its schedule progressively calculates AOS, peak time, and LOS, labeling a pass that spans the day boundary as already or still in sight. Sky starts with **Radio profiles**, which shows passes for satellites with a supported receiver configuration; **All orbits** shows the broader tracking schedule. **Upcoming** starts with passes underway or still ahead today; **Day passes** includes the full local day, and the date arrows show later days. Search by name or NORAD ID to prioritize pass calculation. A searched ID with old elements can request an explicit, tracking-only CelesTrak refresh. To add orbits from your own files, tap **Import orbit file** in Sky and choose TLE text, OMM JSON, or GP CSV with Android's document picker.
4. Select an orbit in Sky to open Target. Curated public/amateur downlinks with a supported receiver configuration appear first; other cataloged frequencies are collapsed under a reference section. A manual foreground receive session can start only when the selected target is above the horizon and its signed catalog and elements are fresh. In automatic-location mode, a fresh phone fix updates the active receiver's predicted pointing and Doppler while the app remains visible; Signal labels paused, unavailable, or stale fixes and holds the last observer. The selected satellite and downlink stay fixed for that session. Signal shows actual sample counts, predicted tuning/Doppler, live graphs, and CRC-checked AX.25 frames separately. For a no-hardware check, tap **Start test tone** in Signal. It generates synthetic I/Q, not a satellite transmission.

## 3D globe

In **Sky → Globe**, drag to rotate Earth and pinch or use the zoom buttons. The observer marker uses the active Location setting. Tap a satellite or search the full catalog by name/NORAD ID, then select **Open Target** to use the existing live tracking and receiver workflow. **View on globe** in Target opens that selected satellite directly.

The selected satellite has an amber orbital arc in the Earth orientation at the shown time and a separate future ground track on the surface. Its panel shows predicted pointing, element age, and the next pass. **Preview this pass**, the next-24-hour slider, and **Play 60×** let you explore predicted motion; **Back to live** returns to current time. Preview time stays in the globe and does not change receiver tuning or reception eligibility. Each rendered scene labels its actual prediction timestamp.

**Radio profiles**, **All orbits**, and **Above horizon** filter the view. The globe samples up to 128 matching records, prioritizing configured receiver profiles and elements nearest the shown time when the sample is selected, and keeps the selected target as an additional exception. Counts distinguish sampled records from all matching records; the above-horizon filter applies only to that subset. Global search still includes every catalog entry. Historical and failed records remain searchable, with positions withheld when unavailable. The native renderer uses the bundled Natural Earth outlines, retains true relative orbital distances, and stops time updates when the globe is hidden or the app is paused. It uses a smaller mesh at normal zoom and a detailed mesh from 2.5× zoom. The Galaxy A30 still drops frames during rotation; a 60 fps interaction rate is not established. Ground visibility and orbital motion are predictions, and do not establish transmission or decoding.

The bundled `app/src/main/assets/sample_catalog.json` is an **unsigned historical demo**. Its orbits age quickly, so its visibility and pass predictions must not be relied on for observing. The app labels this source as demo and disables hardware reception with it. Hardware reception is also disabled when signed catalog data or the selected orbit's elements are more than 72 hours old. The September 26–27, 2026 phone test used a locally signed Space-Track-file cache; no catalog endpoint is deployed or configured for ongoing refresh. To add one, review the data redistribution terms in [NOTICE.md](NOTICE.md), then follow [catalog-service/README.md](catalog-service/README.md) and set the Gradle properties `catalogBaseUrl` (Worker origin, without `/v1`) and `catalogPublicKeyBase64` (base64 of the **raw 32-byte Ed25519 public key**, not an X.509/SPKI wrapper). Keep signing private keys outside this repository. The client fetches the gzip release, requests `/v1/catalog.sig?sequence=N` using its `X-Catalog-Sequence` header, checks the signature and digest before parsing, and falls back to its last verified catalog on failure. The deployed refresh path still needs end-to-end validation.

The catalog builder joins eleven documented CelesTrak OMM queries (Active, SatNOGS, Last 30 Days, Analyst, three debris groups, GPZ Plus, and `NAME=DEB`/`NAME=R%2FB`/`NAME=COOLANT`) with SatNOGS transmitter metadata. Ten queries yielded 30,082 distinct orbits on September 24, 2026. The additional coolant query returned 70 records absent from that cache; a locally signed cache held 30,152 distinct orbits on September 25. The phone verified that cache and showed 30,154 Sky entries with two saved track-only imports. The installed APK and cache now use a persistent signing key outside the repository; the [local fetch/build workflow](catalog-service/README.md) can make later signed phone caches without deploying a service. The installed cache conservatively records the oldest orbital-response timestamp as `sourceUpdatedAt`; signing again does not refresh its source data. These selected queries do not cover every publicly available orbit. Search Sky for a missing NORAD ID to request one additional CelesTrak orbit explicitly. These direct lookups are cached, limited to one request per ID every two hours, and are tracking only; they cannot enable reception. Bulk import can add other orbital records that you supply; the app does not automatically discover every public orbit source. A satellite's pass prediction does not imply that it transmits. Reception separately checks the selected orbit's OMM epoch. Older per-satellite elements are marked as uncertain in the app.

The catalog service also has an optional Space-Track GP source for an approved account. A local `fetch-space-track` command can save one authenticated GP response and SatNOGS metadata outside this repository, then the offline builder can sign it without deploying a service. The scheduled Worker uses the same unfiltered latest-record source when its two secrets are set (`class/gp/format/json`). On September 26, 2026, a user-supplied browser export contained 69,438 distinct records, including all 30,152 IDs in the earlier CelesTrak cache. The offline builder retained that exact ID set, joined fresh SatNOGS metadata, signed a 38.45 MB JSON / 5.69 MB gzip catalog, and installed it on the Galaxy A30; all eight phone instrumentation tests passed. A separate September 27 full-day run processed all 69,438 entries, yielding 234,549 predicted passes and reporting 31 propagation failures without a new crash. Source-dated historical records remain visible but do not receive current predictions; a separate raw-TLE diagnostic also found 31 failures, and the app withholds positions when propagation fails. Its 78.86 MB raw GP file required raising the desktop input limit to 128 MiB; the Android catalog limits remain 100,000 records, 40 MB JSON, and 6 MB gzip. Available old records remain included, with validated source decay dates retained for historical status and prediction/reception cutoffs. A source decay date does not establish physical reentry or its cause. Both builders compare the exact source-ID set with the signed catalog and reject oversized releases rather than truncate the source. They do not fetch every historical element set. The file's origin, exact download time, and upstream completeness were not independently verified. Live CLI login and the Worker remain mock-tested and undeployed. See [catalog-service/README.md](catalog-service/README.md) for setup, source terms, and limits.

Local import accepts two-line or named three-line TLE files (including Alpha-5 catalog numbers), CelesTrak/Space-Track style OMM JSON arrays, and GP CSV files with OMM keyword columns and NORAD IDs up to nine digits. It accepts raw Space-Track UTC date/time strings, checks TLE checksums and orbital fields, reports skipped records, and combines multiple files by keeping the newest imported epoch for each NORAD ID. The private cache retains each orbit's source file name, format, and import time. When an imported or directly looked-up orbit is newer than a signed orbit with the same ID, Sky uses the newer elements for tracking. That override has no receiver profile; reception still requires matching current elements and a downlink in the separate verified signed catalog. Limits are 64 MiB and 100,000 input records per file, 75,000 distinct saved orbits across at most 64 completed imports, and a 96 MiB cache. Import finishes parsing before atomically replacing that cache; an unusable file leaves earlier imports intact.

## Live signal views and SDR tester

Signal has **Receiver / SDR tester / Test tone** sources. Each source offers **Spectrum**, **Waterfall**, **IQ waveform**, **Constellation**, and **Overview** tabs, showing one representation at a time. Active plots read fresh captured samples about ten times per second; a sample-age indicator distinguishes live delivery from waiting, stale samples, stopped sessions and failures. The constellation view is raw I/Q scatter, without symbol recovery or a decoding claim. Stopping retains the last captured plots as past evidence. The generated tone has a frequency slider so its live spectrum/waveform changes can be checked without hardware; this does not test an SDR.

For a hardware check, open **Signal → SDR tester**, connect an RTL-SDR or HackRF One through USB OTG, and tap **Scan USB SDR**. Enter a supported test frequency (default 100 MHz), then tap **Test SDR for 10 seconds** and accept Android's USB prompt if needed. The receive-only check needs no satellite signal, location or catalog. It checks whether USB samples arrive and DSP advances, reports counts/rate/drops, and warns about flat or heavily clipped IQ. Live plots are available during the test and retained afterward. **Stop SDR test** ends it early; leaving the app also stops the test and closes the USB connection. A pass verifies the USB/sample path, while antenna performance, receiver sensitivity and decoding need separate checks.

## USB reception status

- **RTL-SDR:** USB detection, Android permission denial/retry, and the independent ten-second tester were verified on a Samsung Galaxy A30 (Android 11) with an `0bda:2838` dongle and monopole antenna, while ADB used Wi-Fi. Captures at 100 and 145.800 MHz each accepted 10,223,616 complex samples with none dropped; live spectrum, repeat capture, manual Stop and USB cleanup passed. This verifies the USB sample path, not satellite reception or decoding. The foreground receive session still needs a real pass test. The current signed catalog does not enable the ISS 437.800 MHz voice repeater. Supported dongles are discovered by known USB IDs or product name, then Android requests explicit USB permission. Connect a suitable external antenna through the dongle.
- **HackRF One:** The receive-only USB path and native driver compile for Android arm64, including on-device decimation to the app sample rate. Physical-hardware behavior has not yet been verified. No transmit path is implemented.
- **Phone antenna:** Android phone antennas are not exposed as a general-purpose SDR input. The phone's GNSS/location hardware locates the observer; it does not substitute for an antenna attached to the USB SDR.

The **SDR tester** replaces the earlier catalog-dependent three-second USB diagnostic. Satellite reception in Target still requires a current signed catalog, current orbital elements, a supported downlink and a visible pass. The independent tester uses spectrum-only mode and cannot start a satellite decoder or bypass those reception gates. On Android, the RTL-SDR driver requests bias tee power off for passive antennas; this has not yet been measured on hardware.

Receive sessions are started manually and run in a foreground service with a persistent notification and Stop action. Location permission is optional because coordinates can be entered manually. Internet permission is used for configured catalog downloads and explicit CelesTrak orbit lookups. USB permission is requested for the selected device. The app is scoped to curated public/amateur downlinks; it does not authorize interception of private, commercial, safety-critical, or command traffic. Check the rules that apply where you use it.

See [TEST_RESULTS.md](TEST_RESULTS.md) for the phone checks and their limits.

The receiver tunes the nominal RF frequency, updates a baseband Doppler correction from the selected orbit and observer location, and conditionally applies a bounded FM carrier offset estimate from filtered IQ. Signal shows predicted tuning, measured IQ, estimated FM acquisition, and verified AX.25 frame evidence as separate stages; it ages the latest valid frame so an old count cannot appear to mean current sync. After Stop it labels the values as past-session evidence. A CRC-valid HDLC frame also needs valid AX.25 address structure before the receiver counts it as a decoded packet. The carrier estimator and an offset AX.25 frame passed synthetic native tests; the estimator also acquired a synthetic offset on the Android phone and abstained on synthetic noise. These tests do not establish satellite identity or packet sync. The RTL-SDR USB sample path was checked on the phone, but live satellite reception, audio output, and real-pass AX.25 reliability remain unverified. Meteor LRPT imagery decoding is not implemented. A spectrum trace is **not** evidence that a signal has been decoded.
